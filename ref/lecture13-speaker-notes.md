## 이 노트 쓰는 법

- 인용부호 안은 **그대로 읽어도 되는 말**이다. `[…]`는 화면 조작, `⚠️`는 놓치면 뒤가 어긋나는 지점.
- 실습마다 **잘 나온 경우 / 아쉬운 경우** 두 갈래를 적어 두었다. **E2~E4는 출력이 매번 다르다.**
  대사를 외워 가지 말고 「찾을 것」을 보고 그 자리에서 판정한다.
- ⚠️ **E1은 라이브 재현이 아니다.** 모델이 환각을 내 주기를 기다리지 않는다.
  `labs/fixtures/l13-hallucinated-patch.md`에 **틀린 패치를 미리 준비해 두었고, 그걸 그대로 넣는다.**
  **매번 같은 diff, 같은 에러**가 나온다. 이 강의에 **즉흥으로 갈리는 장면은 없다.**
- ⚠️ **fixture를 「방금 모델이 환각한 것」이라고 말하지 않는다.** 그건 사실이 아니다.
  **「이런 패치가 들어온 상황을 만든 것」**이라고 말한다. 이번 강의에서 평가하는 건 **모델이 아니라
  그 패치를 발견하고 되돌리는 절차**다.
- 화면은 **왼쪽 Codex · 오른쪽 README** split. 터미널은 필요할 때만 크게.
- ⚠️ **클립 1의 「심화 (강사)」 여섯 블록은 선택이다.** 시간이 남을 때, 또는 수강생이
  **「그건 왜 그래요?」**로 물어올 때 꺼낸다. **여섯 개를 다 하면 클립 1이 5분쯤 길어진다.**
  다 못 할 거면 **02와 06의 심화를 우선**한다 — 나머지 장의 근거가 그 둘에 걸려 있다.
  **09에도 심화가 하나 있다**(타입이 깨져도 테스트가 도는 이유). 이건 **E2에서 질문이 나오면** 꺼낸다.

## 시작 상태 (강사가 미리 확인)

⚠️ **이건 카메라 밖에서 미리 보는 것이다.** 같은 명령을 **E1의 1단계에서 화면으로 다시** 돌린다.

- Lab 12의 코드·테스트·plan·diff review·검증 기록이 **커밋돼 있어야** 한다.
- 작업 트리가 **깨끗해야** 한다. E1에서 주입할 실패 패치를 판정하려면 출발선이 비어 있어야 한다.
- `labs/fixtures/l13-hallucinated-patch.md`를 **열어서 diff 블록을 눈으로 확인**한다.
  폴백이 아니라 **E1의 입력 그 자체**다. 이게 없으면 이번 강의 실습이 시작되지 않는다.
- `src/payments.ts`에 **`const paidOrder = completePayment(order);` 줄이 그대로 있는지** 본다.
  fixture가 **그 줄을 앵커로 잡는다.**
- `labs/lecture13/inputs/l13-AGENTS.override.md`가 있는지 본다. E1의 2단계에서 저장소 루트로
  복사할 파일이다.
- ⚠️ 저장소 루트에 **`AGENTS.override.md`가 이미 있으면 지우고 시작한다.** 지난 리허설에서
  남은 것이면 **E1 전부터 지침이 어긋난 채로** 돌게 된다.

```bash
git status --short --branch
git log --oneline -3
git log --oneline -3 -- src tests
git diff --stat -- src tests
```

⚠️ **마지막 줄이 비어 있어야 한다.** 비어 있지 않으면 E1 뒤에 생긴 diff가
**이번 실패 패치 때문인지 원래 있던 것인지 구분할 수 없다.** 여기서 멈추고 정리하고 시작한다.

## 리허설 보완 메모

- **E1** — fixture를 **실제로 한 번 적용해 본다.** 모델이 **그대로 넣는지, 고쳐서 넣는지**를
  확인하고, 고쳐서 넣으면 **다시 시킬 때 쓸 한 줄**을 미리 적어 둔다.
- **E1 override** — `cp` → 새 Task → 적용 → 원래 Task로 복귀 → `rm`까지 **한 번 통으로**
  돌려 본다. **Task를 오가는 동선**(창 배치·전환 방법)을 정해 두지 않으면 라이브에서 버벅인다.
  `rm` 뒤에 `git status --short --untracked-files=all`로 **정말 지워졌는지** 확인해 둔다.
- **E1 판정** — `orders`가 `Map`이라는 걸 보여 줄 **`src/store.ts`의 정확한 줄**을 찾아 둔다.

- **E2** — `npm run typecheck`와 `npm test`의 **실제 출력을 미리 찍어 둔다.**

  **타입이 깨져도 테스트는 끝까지 돈다** — 어떤 모양으로 실패하는지는 돌려 봐야 안다.
