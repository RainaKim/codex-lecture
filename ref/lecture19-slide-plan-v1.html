덱 성격

이 덱은 이론 + 실습 덱이다. 19강은 Part 2 · Chapter 4의 셋째 강의로, 지금까지 반복한 검증·점검·확인 절차 가운데 무인으로 맡길 수 있는 것을 가려내고, 맡기기 전에 멈추는 조건과 사람이 재개하는 지점을 만든다. 커리큘럼 정본의 지침대로 독립 기능 소개가 아니라 기존 Desktop App 중심 흐름에서 반복되는 부분을 떼어내는 구성이다. 전체 구성은 표지(01) → 반복과 위임(02~06) → 실습 큐 07 → 표면과 자동 실행 권한(08~12) → 실습 큐 13 → Skill 승격(14~16) → 실습 큐 17 → 중단 조건과 예약(18~20) → 실습 큐 21 → 마무리(22)이고, 실습 큐 E1~E4는 클립 1~4에 하나씩 온다. 클립 배분(예상 · 리허설 후 확정): 클립 1 — 반복 작업의 후보 판정(약 10분 · 01~07) / 클립 2 — 어디서 무엇을 하나과 자동 실행 권한(약 10분 · 08~13) / 클립 3 — Skill 승격(약 7분 · 14~17) / 클립 4 — 중단 조건과 예약 생성(약 8분 · 18~22).

실습 결과를 슬라이드에 넣지 않는다. 네 후보가 적합 · 조건부 · 수동 유지 중 어디에 속하는지, 어느 후보가 자동 실행 권한 때문에 걸러지는지, 승격할 후보의 이름과 SKILL.md 본문, 두 세션의 비교 결과, 중단 조건의 상한 값과 Scheduled 생성 화면은 모두 실습 또는 라이브 데모에서 나오는 것이다. 04는 후보 이름과 입력 종류만, 06은 판정의 뜻만, 18은 중단 유형과 감지 신호만 적는다. 실습 큐 네 장(07·13·17·21)은 17강 10 · 16 · 20 · 22와 같은 큐 컴포넌트·좌표(레드 「실습」 배지 88%/15.5% + 헤드라인 + 위 카드 30~46.5% 세 행 + 아래 2열 50.5~78%)를 그대로 쓰고, README의 목표 · 문맥 · 제약 · 완료 조건을 순서 칩 · 원칙 한 줄 · 확인할 것으로 압축한다.

공식 문서 근거(슬라이드에 사실로 쓴 것): Scheduled 관리 화면은 ChatGPT Desktop 앱 · 웹에만 있고 Codex CLI · IDE에는 없다(08 · 10). 예약 실행은 무인이며 기본 sandbox를 쓰고 조직 정책이 허용하면 승인 정책은 never다(09). read-only는 파일 수정 · 네트워크 · 컴퓨터 앱 사용을, workspace-write는 workspace 밖 파일 수정 · 네트워크 · 컴퓨터 앱 사용을 막는다(10). Desktop 앱의 예약 prompt에서 $skill-name으로 Skill을 직접 호출할 수 있다(14 · 20). 로컬 프로젝트 task는 컴퓨터와 앱이 켜져 있어야 하고 잦은 일정은 worktree를 쌓을 수 있다(20). Skill은 SKILL.md(name · description 필수) 폴더이고 repo 위치는 .agents/skills다(14). 공식 스킬 문서에는 Skill과 Scheduled task의 관계 설명이 없다 — 03의 책임 분리(Skill = 일하는 방법, Scheduled = 언제)는 이 과정의 설계이며 슬라이드에도 그렇게 표기했다.

17강 · 13강 플랜과 같은 토큰 · 좌표 문법(킥커 12.18% · 헤드라인 18.8%)을 그대로 쓰고, 표지는 assets/cover19.png로 gen2.py가 01을 이미지 표지로 교체한다 — 01의 텍스트 표지 목업은 PNG와 같은 문구를 적어 둔 대체 표기다. 스트립은 쓰지 않는다. 마지막 슬라이드의 Chapter 4 흐름은 역할 분리 → Issue → 후보 판정 → Skill → 중단 조건 → PR 후보로 두고 19강이 세 노드를 차지한다.
