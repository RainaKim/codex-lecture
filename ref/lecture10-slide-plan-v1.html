덱 성격

이 덱은 라이트 개념 덱이다. 슬라이드는 개념 앵커만 잡고 상세 설명은 스피커 노트가 맡는다. 10강은 Chapter 2의 네 번째 강의로, 7강 정책(도메인 판단) → 8강 요청 구조(Issue template) → 9강 계획 구조(Plan template)에 이어 매번 반복되는 요청 자체(프롬프트 셋)를 repo에 고정한다. 커리큘럼 정본은 「테스트 보강, PR 설명, diff self-review처럼 반복되는 작업을 prompt와 checklist로 고정해 매번 새로 설명하지 않게 한다」와 「테스트 보강 prompt: 새 기능이 아니라 빠진 케이스를 찾고 의미 있는 assertion을 추가하도록 요청문을 만든다」 두 줄이다. 이건 재사용이지 자동 실행이 아니다 — 자동 실행은 19강이고, Lab 10 E4의 설계 질문에도 「자동 호출보다 사람이 선택해야 할 상황은?」이 있으므로 슬라이드 어디에도 자동 호출을 암시하는 문구를 두지 않는다. 앱 코드는 이번에도 v0 무변경. 구성은 표지·리캡(01·02) → 오늘의 지도(03) → 이론 앵커 04·05 → 실습 큐 06 → 이론 앵커 07 → 실습 큐 08 → 실습 큐 09 → 실습 큐 10 → 마무리(11). 실습 큐 네 장(06·08·09·10)은 9강 큐 컴포넌트(레드 「실습」 배지 + 헤드라인 + 위 카드 + 아래 2열)를 따르되, 위 카드에 이번에 만드는 것 · 입력/출력(또는 채울 칸) 칩 행 · 원칙 한 줄 세 행을 담기 위해 위 카드를 30~46.5%로 키우고 아래 2열을 50.5~78%로 내렸다(네 장 동일 좌표). 클립 배분(실습 N은 클립 N에 온다 — 9강과 같은 규칙): 클립 1 — 반복 작업을 왜 고정하나 + 테스트 보강(약 16분 · 01~06) / 클립 2 — PR 설명(약 10분 · 07·08) / 클립 3 — self-review(약 7.5분 · 09) / 클립 4 — 연결과 마무리(약 7분 · 10·11). 도입·이론 두 장이 모두 클립 1에 들어가 클립 1이 가장 길다(7·9강도 같은 형태). 9강 플랜과 같은 토큰·좌표 문법(킥커 12.18% · 헤드라인 18.8% · 스트립 79.5%)을 그대로 쓴다. 다이어그램 장(04)은 9강 04처럼 큰 토큰(t mid 10.5px · t 8.2px)만 쓴다.
